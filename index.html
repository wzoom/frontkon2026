01 · The problem

Deleting a flag is a judgement call, not a parse.

Only 1 in 5 flags is safe

Dec 2025: 3,274 flags, 639 safe to delete. Why the rest are not (a flag can fail several checks):

One flag is five artefacts

  • a React hook call
  • an enum in a capability registry
  • a GraphQL @include(if:) directive
  • translation keys × 8 locales
  • a Terraform resource

Plus tests, dead components, now-unused imports.

02 · Architecture

Code before, code after, AI in the middle.

Triggercron · dispatch · webhook
DiscoverLaunchDarkly API
Pre-checkscode
Agentprompt + allowlist
Post-processcode
OutputPR · Jira · Slack

Stack

GitHub Actions: 22 workflows, 27 composite actions. TypeScript scripts (~16k lines + ~9k tests). One matrix job per flag.

Provider-agnostic

One repo variable: AI_AGENT_PROVIDER = rovo | copilot | claude. Same prompts, same contracts. Switched providers in 2026 without touching a prompt.

The rule

Anything that can be decided by code is decided by code. The model only does what needs judgement: editing the right lines in the right files.

03 · What is in each box

Four out of five flags never reach the AI.

before · code
  • 100% on in staging and production for 14+ days
  • boolean; no prerequisites; no dependents; not tagged ignore-cleanup-bot
  • no existing ticket or open PR (dedupe)
  • owner resolved from git history → ticket routed to that team
  • throttle: max 5 PRs per team per week
agent
  • one markdown prompt per repo type (frontend, Go, Node, Ruby…)
  • tool allowlist: file tools + 34 shell commands, default deny
  • git commit / git push explicitly disallowed
  • 10-minute budget, no questions — nobody is there to answer
  • folder deletions via a file contract, executed by the pipeline
after · code
  • if HEAD moved, git reset --mixed — the agent's commit is undone
  • GraphQL type generation, lint-staged (lint + format)
  • pipeline commits, opens the PR + Jira ticket, posts to Slack
  • repo CI runs the tests like any human PR
  • the owning team reviews and merges — never the bot

04 · The agent step

The whole agent invocation fits on a screen.

# tools: file edits + an allowlist read from a text file
ALLOWED_TOOLS="Read,Glob,Grep,Edit,Write,TodoWrite,Task"
while read -r cmd; do ALLOWED_TOOLS+=",Bash(${cmd}:*)"; done < agent-allowed-commands.txt

ORIG_HEAD=$(git rev-parse HEAD)
claude -p "$PROMPT" \
  --permission-mode acceptEdits \
  --allowedTools "$ALLOWED_TOOLS" \
  --disallowedTools "Bash(git push:*),Bash(git commit:*)" \
  --append-system-prompt "$(cat agent-ci-instructions.md)" \
  --model sonnet --output-format stream-json > stream.jsonl

# it committed anyway? keep the changes, drop the commit
[ "$(git rev-parse HEAD)" != "$ORIG_HEAD" ] && git reset --mixed "$ORIG_HEAD"

# success = the result event, not the exit code (crashes exited 0)
jq -c 'select(.type=="result")' stream.jsonl | tail -1

Excerpt, simplified. The Copilot and Rovo actions follow the same contract.

05 · The feedback loop

Every review comment becomes a rule.

1 · Ask for it

Every bot PR opens with: "Please comment on anything the AI forgot to clean up or messed up. Your input directly improves the prompt."

2 · Write it down

Comments go into a pattern library mined from merged PRs, then into the prompt. Prompt: 19 lines → 771 lines, 44 revisions. Most edits cite the PR that caused them.

3 · Measure it

Flag-code PRs merged with zero human commits: 29% in Dec 2025 → 83% in Sep 2026. All lanes: 65.5% (Piranha: 65%).

Confounders: provider switch (Jun 2026) and a newer default model (Jul 2026) landed in the same window.

07 · Adoption

Perfect PRs still waited 29 days.

The problem was attention

Dec 2025: small, green, correct PRs, median 29 days to merge. First weekly report: 0 flags cleaned.

What fixed it

  • weekly Slack report: per-team leaderboard and oldest open PRs
  • every PR routed to the owning team with a ticket
  • per-team throttle so nobody gets flooded
  • a mascot — a bot with a face gets reviewed

Result

Median days to merge, by month: Dec 29 · Jan 12.4 · Mar 6.4 · May 2.9 · Aug 2.2 · Sep 1.3.

09 · Start tomorrow

Pick something boring, repetitive and easy to verify.

cheapest

GitHub Agentic Workflows

A markdown file in .github/workflows/. GitHub runs the agent and opens the PR. github.github.com/gh-aw

middle

Your workflow + an agent CLI

A prompt, ~50 lines of YAML, Claude Code or Copilot CLI with an allowlist — slide 05 is most of it.

only if needed

A full pipeline

When "is it safe to touch?" needs several APIs and a dependency graph. Ours: ~25k lines of TypeScript, ~11k lines of YAML.

Five rules

  • Code before and after, AI in the middle. Gates and verification are deterministic.
  • AI never commits, AI never merges. Enforce it in tooling, not in the prompt.
  • Every review comment becomes a rule. Ask for it in the PR body.
  • Every PR has an owner. Route it to the team, throttle it.
  • Give it a face. Adoption is the hard part.
